# Desktop client (proposed Electron)

Read README.md here, the root AGENTS.md and PUBLIC_BOUNDARY.md before changing this component. The design documents behind this client stay outside this repository; never add them here.

- Packets A, C, D and E parts 1–4 (pure state, contracts, Electron-free main-process, job-runner, fixture-provider and preload modules with injected ports; part 4 adds macOS microphone permission and capture through a hidden capture window) and B parts 1–3 (an accessible Electron shell: Electron Forge 8 + Vite, React 19, TypeScript 7, Playwright, wired to D's offline synthetic main, with audio import, transcription, the Replace/Keep candidate and a recording UI in which Stop asks before transcribing). Dependencies are pinned exactly; adding or upgrading one is a reviewed change.
- Main validates every renderer payload itself (caller frame, version, exact fields, session, epoch, route policy, limits). Never add a generic invoke/send or a channel that accepts paths, URLs, headers, model overrides or credentials; revise the threat model and contract before adding a privileged operation.
- Checks: `npm test` (Node 22.18+, no install), then after `npm ci`: `npm run typecheck`, `npm run test:e2e` and `npm run test:electron` (Packet D's offline test in a real Electron window; needs Electron's binary and, on Linux, a display). Use only erasable TypeScript syntax so Node can strip types for unit and contract tests.
- Main keeps `sandbox`, `contextIsolation`, no Node integration, no navigation/new windows, and denies every permission except audio for the hidden capture window while a macOS recording is opening or open (E part 4). Never grant the app window media access. Keep the strict CSP in `index.html`; render model output as text only.
- Renderer code may not use Node, the filesystem, sockets or secrets. Contracts stay pure data with no Electron or HTTP objects.
- Keep stale/late replies from replacing edits, exact route-identity checks, the unknown-outcome gate and the copy-confirmation rules. Add a failing regression before changing reducer behavior.
- The unknown-outcome gate is app-wide and clears only through main-side `reconcile` or the user's explicit Acknowledge in Inspect (`acknowledgeOutcome`), for a route in main's `acknowledgeRoutes`: today only the `local-base-rewrite` route, and only while it requires the "synthetic" marker (`baseRewriteAcknowledgeable`). Main reports every unknown outcome to every session, so a reload reaches Inspect. Never acknowledge automatically or offer a retry that bypasses Inspect, never make a fixture route acknowledgeable, and never add a route to `acknowledgeRoutes` without that route card's own decision and a revision of the threat model.
- Fixtures are fictional text only. No live provider, microphone or network in unit tests. The one exception is `tests/contract/loopbackHttp.test.ts`, whose throwaway server listens on 127.0.0.1 inside the test process.
- Provider adapters declare their own approved `timeoutMs` and call `dispatched()` immediately before sending; if it throws, do not send. After dispatch, aborts and timeouts are unknown outcomes, with one exception: a cancel while the local base rewrite route's transport waits for the service's identity proof. The body has not left then, so the transport reports NotSent and the job is `route_unavailable` (a job timeout is still the runner's `unknown_outcome`). Never retry, fall back or substitute a route. Source may import no Node built-in except `node:crypto`; only the Electron chooser binding may use `node:fs/promises`, to read the one file picked, and `src/main/providers/identityFile.ts`, to read the local base rewrite route's server identity file; only `src/main/providers/loopbackHttp.ts` may use `node:http`, for an approved route card's single `127.0.0.1` destination (the local base rewrite route); and only the Electron entry files, the chooser and the capture binding may import Electron (enforced by `tests/contract/offline.test.ts`).
- The local base rewrite route is off unless main is launched with `XENON_REWRITE_ROUTE=local-base-rewrite`; then rewrites go to `127.0.0.1:30113`, a job is sent only if the transcript, and the steering when not empty, contain "synthetic", and its body goes out only after the service proves its identity on that connection (`serverIdentity.ts`; never make the check optional for this route). The route's allowance ends at `BASE_REWRITE_SETTINGS.allowedUntil`, the end of 2026-12-31, Pacific time, by this machine's clock: from then on every job is `route_unavailable` before dispatch, checked at every job. Never move that date without the owner's decision. Its destination, model and limits are compiled in (`src/main/providers/baseRewriteRoute.ts`); never let a renderer, a reply or the environment change them (the identity file sits under the home directory Electron reports, which follows `CFFIXED_USER_HOME`; that is the one environment input, inside the same-user boundary). Real samples need the owner's separate authorization.
- Inspect media bytes, never names or claimed types; no path may reach the renderer. Platform dialogs and devices are injected ports that open only from an explicit intent, never at launch.
- Prompt for microphone permission only from a deliberate Record when the state is `not_requested`; never at launch, on focus or on retry. One capture app-wide; closing, navigating or replacing a session must stop any recording, and a failed or hung stop must discard at the device.
- Before the first rewrite to a route that leaves the app (any mode but `fixture`), ask once per session where the text goes (`src/renderer/sendConsent.ts`); nothing is sent until Send, a blocked Send records no consent, and after either answer focus goes to the status line.
- A transcript never overwrites existing text without an explicit Replace. Job references carry their kind; events of one kind must never settle the other.
